## 好不容易想开工，却卡在找东西

有灵感的时候，你可以一口气做几个小时。

原型跑起来了，问题解决了，还顺手开了两个新坑。然后被一件事打断，项目就这样放下了。

过了几天，终于又有一点力气想继续：

> “我记得做过这个……文件在哪？”
>
> “上次是和哪个 AI 聊的？Codex？Claude？还是另一个？”
>
> “那个问题到底解决没有？当时为什么选这个方案？”

翻聊天，找文件，重新给 AI 讲前情。等终于拼出个大概，那点想开工的劲也快耗光了。

如果你有 ADHD，或者也常常在**点子很多、成果零散、放下后很难重新开始**之间打转，这个项目就是从这样的日常里长出来的。

**如果每次继续，都要先整理整个房间，那「开始」就太贵了。**

## 我想要一根魔法棒

房间可以暂时乱着。伸手的时候，能拿到想要的东西就好。

Memory Hub 把本地 AI 工作记录和项目文本放进一个可检索的入口。你可以从一个关键词、一段报错、一个模糊的项目印象开始，找回相关记录和出处，再交给正在用的 Agent 继续梳理。

它想降低的，是每次重新开始前的那一大段准备工作：

**从「我记得做过这个」，走到「找到了，今天先接着做一点」。**

## 它怎么帮你接回来？

### 🧩 只记得一点，也能先找起来

你可能忘了项目名，但还记得「猫咪桌宠」。

```text
猫咪 桌宠
```

先用这些线索搜索，查看相关记录、项目路径和来源。基础搜索使用本地关键词检索；可选的语义检索能帮助寻找表述不同的相关内容。

不必在搜索之前，先把所有聊天重新分类、命名、写成笔记。

### 🔄 换了 Agent，少讲一遍前情

今天用这个 Agent，明天试另一个。为了额度、为了新功能，或者只是想换一种思路，任务很容易东一个西一个。

把 Memory Hub 的接入提示词交给具备本地工具访问能力的 Agent，你就可以这样开口：

> “继续之前那个网页收藏整理工具。先查一下历史记录，告诉我做到哪了、还有什么没确定，再帮我选一个今天能做的小步骤。”

Agent 先检索，再根据找到的证据整理前情。**记录够用时，就少从头解释一次；证据不够时，也应该明确说不确定。**

这是一种使用方式示例，实际能找回什么，取决于已经接入和同步的本地记录。

### 📍 找到以后，还能回到出处

“好像做过”很难让人安心接着干。搜索结果保留来源信息，方便核对原记录和项目位置。

部分来源只能提供会话标题或工作区等元数据，会标为 `metadata_only`。这些信息能帮你定位线索，但不能代替聊天正文。

### 🌱 先用起来，需要时再加能力

基础搜索不需要模型，也不需要 API key。你可以先接入已有记录，用浏览器界面找东西，再按需要开启语义检索、重排或带来源的 AI 问答。

| 你现在想做什么 | 可以怎么用 |
| --- | --- |
| 找回做过的东西 | 用关键词搜索本地记录与项目文本 |
| 接着做旧项目 | 把检索结果交给 Agent，梳理前情和下一步 |
| 换一个 Agent 继续 | 通过提示词配合 HTTP、MCP 或命令行接入 |
| 回顾以前的决定 | 查看相关原文；可选 AI 问答协助归纳 |

## 让 Agent 接着帮你

首次配置并启动 Memory Hub 后，把 [接入提示词](PROMPT-给其他AI.md) 交给你正在使用的 Agent。

提示词会告诉它：什么时候搜索、怎么核对来源，以及证据不足时不要编造历史。当前服务地址和接入信息可从 `/api/agent-prompt` 获取。

**接入前提：Agent 需要能访问运行 Memory Hub 的电脑，并支持本地 HTTP、MCP 或命令行中的至少一种。** 只有普通聊天框、无法调用本地工具的 AI，不能仅靠粘贴提示词连接服务。

MCP 客户端可使用虚拟环境中的 Python 作为可执行文件，传入参数：

```text
-m memory_hub.mcp
```

具体接入方式见 [提示词与工具说明](PROMPT-给其他AI.md)，薄接入说明位于 [skills/](skills/)。

## 开始使用

目前提供源码安装，以下步骤面向 **Windows + Python 3.11 或更新版本**。

### 1. 下载并安装

在 PowerShell 中运行：

```powershell
git clone https://github.com/Dumpling-Dragon/memory-hub.git
cd memory-hub
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

### 2. 选择要找回的记录

将 [config.example.json](config.example.json) 复制到 `%LOCALAPPDATA%\MemoryHub\config.json`，按照 [配置说明](docs/configuration.md) 填写来源路径。目标目录不存在时，请先创建；已有配置则直接编辑。

可以先保持模型相关开关关闭。`project_roots` 可添加项目目录；本地 Agent 连接器也会尝试发现已有工作目录。

Gemini、元宝网页聊天需要先导出到本地，再配置 `web_export_roots`，不会直接读取网页账号。来源格式和限制见 [来源接入](docs/sources.md)。

### 3. 同步，开始搜索

```powershell
.\.venv\Scripts\memory.exe sync
.\.venv\Scripts\memory.exe serve
```

浏览器打开 <http://127.0.0.1:17888>（默认地址；修改过端口时以配置为准）。

**试着搜一个你还记得的旧项目关键词。先找回一件东西，就够了。**

<details>
<summary>更多命令与可选桌面入口</summary>

```powershell
.\.venv\Scripts\memory.exe search '关键词'
.\.venv\Scripts\memory.exe continue '旧任务线索'
.\.venv\Scripts\memory.exe sync
.\.venv\Scripts\memory.exe embed --limit 100
.\.venv\Scripts\python.exe -m memory_hub.mcp
```

`continue` 是旧任务线索的检索入口，后续行动由你或接入的 Agent 决定。`embed` 需要先配置并启用 embedding 模型。

Windows 桌面控制窗是可选组件。安装 `.[desktop,test]` 后，按 [桌面控制窗说明](desktop-control/README.md) 构建或运行。桌面入口仍依赖本地服务，不是独立服务器发行包。

</details>

## 你的记录会去哪里？

Memory Hub 使用本地 SQLite 索引，运行数据保存在 `%LOCALAPPDATA%\MemoryHub`。来源连接器只读原文件，默认服务监听 `127.0.0.1`。

- **基础关键词搜索：** 在本地完成，不调用模型。
- **可选模型功能：** 开启 embedding、重排或 AI 问答后，相关文本可能发送到你配置的模型端点。隐私、保留和计费规则取决于提供商。
- **脱敏：** 默认尽力遮蔽明显的 key、token 和 password，但不能保证识别所有敏感信息。`full_memory_mode` 默认关闭；明确开启后才允许模型接收未脱敏的召回内容。
- **来源范围：** 默认跳过密钥、认证文件、浏览器缓存、二进制和大文件。未配置或不可用的来源会显示状态，不会假装已经导入。

需要在受控网络中使用时，可通过 `api_token_env` 配置 Bearer 认证。认证与监听地址分别配置，公开绑定前需设置网络访问控制。详见 [配置说明](docs/configuration.md)。
